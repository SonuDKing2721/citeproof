# Citeproof: Related Work and Gap Review

**Reviewed:** October 29, 2026

**Scope:** Every project, paper, package, and provider pattern named in `Citeproof_Related_Projects_and_Improvements.md`, compared with the current local checkout. Volatile GitHub star counts are omitted. Repository and benchmark claims below are identified as author-reported when they come from project documentation.

## Summary

Citeproof is an issue-to-code localization prototype. Its core promise is narrow: two bounded investigators return candidate source locations, and a local checker verifies that cited paths, exact quotes, line ranges, and optional Python symbols match a pinned checkout. A checked quote supports the cited source text and location; it does not establish that the proposed diagnosis is right.

The strongest design references are Agentless for hierarchical localization and code-archaeologist for deterministic evidence seeding and an explicit citation guard. The code-comprehension paper is the closest research on code citations, but its main system combines hybrid retrieval, import-graph expansion, and generation; it is broader than a post-hoc checker. These references support structured locations and clearer evidence outcomes. They do not establish that Citeproof is novel or that its two investigators outperform a simpler baseline.

The supplied note is partly stale. The local project already has eight cases, a request-budget-matched single-agent control, pinned clean checkouts, cached traces, and human review kept separate from citation checks. A November 1 follow-up added free-route attempts on Pydantic, HTTPX, sse-starlette, and openai-python. Only HTTPX and the earlier Click comparison completed with equal request counts; Pydantic differed by one request, the SSE baseline timed out, and both OpenAI investigator calls timed out. The participant marked the Pydantic diagnosis supported; Click #3449 also has a separate partly supported review. Evidence remains too small and smoke-case-heavy for any broad accuracy or diagnosis-correctness claim.

## Direct-peer analysis

### Localization pipelines: Agentless and Agentless Mini

Agentless gives the clearest structural comparison: it first narrows files, then classes/functions, then edit lines. Its repair results should not be placed next to Citeproof's `hit@1` or `recall@3`, because a system can find the correct file and still fail to make a patch, or produce a patch after imperfect localization. Agentless Mini narrows its first stage to files, then passes whole-file content to repair. That makes it a useful reference for file-ranking metrics, but not a proven cheap or no-cost runtime route. Its published vLLM example uses a 70B model and four-way tensor parallelism.

Citeproof's current scorer aggregates verified files across the required investigators. It does not yet expose a separate finding-order ranking for each investigator. The approved improvement adds that view while preserving the pair metric and the request-matched single-agent control. It remains a localization proxy based on merged-fix files, not a diagnosis score.

### Code evidence and citation guards

The code-comprehension preprint checks whether a cited file/range overlaps retrieved source and reports separate retrieval and citation results. That resembles Citeproof's mechanical boundary, but Citeproof additionally checks exact quoted text and can require a Python AST symbol to contain the cited range. The paper's 1,080 observations are 180 questions across six models in its own evaluation, not 1,080 independent projects or verified diagnoses. Its reported 100% is a bounded result of its verification procedure on those responses, not proof that any checker establishes semantic correctness.

Code-archaeologist is the closest hackathon-style neighbor because it combines deterministic evidence collection, bounded tool use, and a guard that drops claims without ledger evidence. Its current public repository is available, so the note's older “not on GitHub” description is outdated. The tool's historical-intent task differs from Citeproof's issue-localization task. Its useful idea—seed with evidence available without a model call—is already partly present in Citeproof's diagnostic/API hint seeding and should be credited as an existing implementation, not listed as a missing feature.

### Simple agents and endpoint adapters

SWE-agent and mini-SWE-agent are useful engineering references for a small, inspectable agent loop. Both target issue repair, and mini-SWE-agent explicitly uses bash. Citeproof's no-shell, read-only tools are a deliberate safety and evaluation boundary. Aider, Cline, and Agentless Mini show that an OpenAI-compatible API can reduce adapter work, but they provide no evidence that an endpoint is free, stable, or suitable for this model.

## Citeproof's current position and gaps

The [local case manifest](../citeproof/cases.py) contains eight cases across five projects: Click (four cases), HTTPX, Pydantic, sse-starlette, and openai-python. Issue text and gold labels are separate, and each curated checkout is pinned to a clean pre-fix commit ([pin checks](../citeproof/repo.py)). The application has two investigator strategies ([orchestration](../citeproof/orchestration.py)), bounded read-only repository tools, local path confinement, exact quote/line checks ([current checker](../citeproof/checker.py)), and an optional evidence verifier. The verifier cannot add citations or establish diagnosis truth.

The deterministic checker emits stable outcome codes for path, range, quote, and symbol checks. It can relocate a unique exact quote anywhere in the same file when the corrected range still passes the file and symbol checks, and it preserves the claimed and corrected ranges separately. The UI displays both ranges; evidence overlap and verifier evidence use the corrected range when present. These checks establish citation integrity, not diagnosis correctness. The [current evaluator](../citeproof/evaluation.py) reports pair-level and per-investigator file-localization scores, and the project retains a [request-budget-matched single-investigator control](../citeproof/benchmark.py) with a saved [Click #3449 comparison](../data/benchmarks/click-3449-budget-comparison.json). These facts replace the supplied note's “no baseline yet” and “two curated cases” snapshot.

Most historical run variants are repeated Click #3449 experiments. The October 29 [Pydantic #13957 run](../data/benchmarks/pydantic-13957-quality-gates-20261029.json) timed out before a baseline, and the [post-follow Click #3449 run](../data/benchmarks/click-3449-post-follow-quality-20261029.json) also timed out; these remain incomplete availability observations. A November 1 [Pydantic comparison](../data/benchmarks/pydantic-13957-budget-comparison-20261101.json) returned one checked finding from investigator A and a matching single-agent result, but its 8-vs-7 actual request counts make the comparison incomplete. The participant marked this diagnosis supported. A new [HTTPX comparison](../data/benchmarks/httpx-2883-budget-comparison-20261101.json) completed with 10 requests on each path and tied localization scores; it is a historical, contamination-prone smoke case. The [SSE comparison](../data/benchmarks/sse-starlette-211-budget-comparison-20261101.json) has a complete pair but a timed-out baseline; the [OpenAI comparison](../data/benchmarks/openai-python-3811-budget-comparison-20261101.json) timed out both investigators before a baseline. The [cached-pair review](../data/benchmarks/click-3449-cached-demo-rechecked-human-review-20261029.json) and [live-symbol-lookup review](../data/benchmarks/click-3449-live-final-symbol-lookup-human-review-20261029.json) refer to the same issue; they count as one distinct reviewed case. HTTPX and SSE human diagnosis reviews are still pending. The two supportedness labels cannot calibrate diagnosis correctness across the benchmark.

The approved first improvements are deliberately narrow:

1. Add typed exact-source outcomes and safe relocation of a unique exact quote, retaining the model's claimed range and any corrected range separately.
2. Show each finding's citation-support state and keep rejected quotes and explanations visible. “No checked source support” must not be presented as “wrong diagnosis.”
3. Add per-investigator file ranks derived from finding order, with hit@1, reciprocal rank, and recall@3. Keep the pair and budget-matched baseline results separate; do not add an aggregate correctness score without independent human reviews across distinct cases.

No fuzzy quote matching, semantic normalization, minimum quote length, embeddings, code graph, shell access, provider change, paid call, or code copied from another project is justified in this phase.

## Model route and event constraints

Meta's [Muse Glimmer page](https://dev.meta.ai/models/muse-glimmer) describes a 30B Apache-2.0 open-weight model. Meta's [quantization guide](https://dev.meta.ai/resources/blog/build-with-muse-glimmer) says the roughly 4-bit model uses under 20 GB for weights and recommends a 24–32 GB envelope for weights plus runtime memory. The workstation inspected for this project has an RTX 2050 with 4 GB VRAM ([inference-route notes](CITEPROOF_INFERENCE_ROUTE_RESEARCH.md)), so local GPU inference is not a realistic no-cost path on that machine.

The [NVIDIA API Catalog listing](https://build.nvidia.com/meta/muse-glimmer-30b/build) currently labels a Muse Glimmer endpoint as free and available. The November 1 attempts show intermittent access: the HTTPX comparison completed, the Pydantic pair and baseline completed with an actual-request mismatch, the SSE pair completed while its baseline timed out, and both OpenAI investigator calls timed out. “Listed as free” is not the same as “reliably available.” The October 29 research review made no model calls; these later reports are separate run evidence, not an endorsement of uptime.

Meta's [model API documentation](https://dev.meta.ai/docs/models) distinguishes hosted API models from self-hosted open weights; its [pricing page](https://dev.meta.ai/docs/pricing-rate-limits) describes pay-as-you-go billing. Any hackathon credits need to be confirmed for this participant account before treating that route as zero-cost. The partner credits listed by Cerebral Valley are selective, so they are a possible no-cost route only if the user receives access.

The [Cerebral Valley event listing](https://events.cerebralvalley.ai/e/meta-ai-developer-hackathon) describes $100 credits from Baseten, Modal, and Fireworks for select participants. These are conditional event offers, not guaranteed credits for this account. Meta's [official event page](https://dev.meta.ai/events/global-hackathon) lists open-weight use and a November 4, 2026 submission deadline at 9:00 PM ET, but as of October 29 it still says the Official Rules “will be published” before the October 26 kickoff and does not link the rules. Therefore the public pages do not confirm the exact open-weight bonus conditions. Use no paid fallback and do not claim bonus eligibility until the accepted rules or organizer confirm it.

## Sources and interpretation policy

Repository README performance claims are self-reported unless corroborated by a benchmark maintainer. The arXiv item is cited as a preprint and described by its own methodology and result statements. PyPI descriptions and company engineering posts are treated as project/vendor statements, not independent evaluations. No source's bug-fix score is used as a Citeproof localization score.
